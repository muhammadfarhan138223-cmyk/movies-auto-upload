# Security model and limitations

## Boundaries

- Local Node agent binds only to `127.0.0.1`; requires local Host header and same-origin POST custom header to prevent basic DNS rebinding / CSRF. **It is not a multi-user or publicly exposed service.** Local processes and trusted users on the computer may still access it.
- Video bytes go directly from laptop to provider upload destinations using provider API credentials; no Vercel, Supabase, or GitHub Pages video traffic.
- Agent `.env` includes host API keys and (optional) Supabase agent password. This file is git-ignored. Store in a Windows account with disk protection.
- Mobile static source and public Supabase URL/publishable key are public. The Supabase RLS policy, not code obfuscation, enforces authorization.
- Mobile login uses a pre-created, confirmed owner email; separate agent login is used for updates. No service_role/secret key is shipped with the code.
- Remote status contains filenames, result URLs and progress; treat this as private metadata, even if files themselves are unlicensed or harmless. Browser persists a login refresh token in localStorage. Use a personal phone lock and sign out on shared devices.

## Actions before making GitHub repository public

1. `git status --short` should not include `.env`, files under `data/`, movie video files, CSV exports or personal screenshots.
2. `git ls-files` to review exactly what will be published.
3. Do not paste Streamtape or DoodStream login/password, agent password, service_role key, or user session tokens into issues or README examples.
4. Rotate leaked credentials immediately through the provider/Supabase dashboards.
5. Test Supabase RLS as unauthorized user, owner, and agent. Without RLS tests the mobile setup is **not verified secure**.
6. Consider GitHub issue reporting with redacted logs and versions only.

## Known limitations

- A successful provider API response doesn't guarantee public playback. Hosts and embed domains may change or stop resolving.
- HTTP multipart uploads may not support byte-range resume. Interrupted responses are marked `review` to avoid duplicate uploads.
- A malicious app already executing on the same Windows account may be able to control localhost endpoints. Use dedicated OS accounts or do not run untrusted software.
- Auto shutdown will close Windows after an explicit opt-in; unsaved work in other applications can be lost. Do not use on a damaged or overheating laptop.
- GitHub Pages is static; remote PWA cannot control Windows or transfer video files.
- Remote Supabase Sync publishes only the most recent 500 jobs and requires internet, valid credentials and project quotas. If laptop is off, displayed data is stale.
- Provider upload URL generated by an API may be on a different domain; code enforces HTTPS but cannot independently guarantee the remote server is safe. Treat host APIs as trusted services.

## Reporting a vulnerability

Open a private security advisory in the GitHub repository once public, or contact the maintainer privately. Do not publicly paste credentials or sensitive filenames.
